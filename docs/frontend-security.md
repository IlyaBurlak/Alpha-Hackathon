# Безопасность фронтенда

Аудит клиента (`client/`) и его nginx. Сервер и ML проверяют права сами; всё, что решает клиент (экраны по ролям), только удобство.

## Что сделано

| Что | Как |
|---|---|
| Токен | по умолчанию хранится в `sessionStorage`: живёт в одной вкладке и исчезает при её закрытии. Только если сотрудник отметил «Запомнить меня» (по умолчанию выключено), токен кладётся в `localStorage` и переживает закрытие вкладки; новый вход заменяет токен в другом хранилище |
| Срок токена | токен с истёкшим `exp` (в любом из двух хранилищ) забывается при запуске приложения, а не при первом упавшем запросе |
| Персональные данные | черновик анкеты (телефон, почта, выручка, залог) лежит в `sessionStorage`, а не в `localStorage`; при выходе из кабинета (и при 401) чистится всё хранилище вкладки |
| Адрес запроса | `id` заявки из адреса страницы кодируется (`encodeURIComponent`) и не может добавить или поднять сегмент пути (`../../users/info`) |
| Панель `/admin` | открыта только вошедшему сотруднику, без входа уводит на `/staff/login` |
| Заголовки nginx (клиентский образ и `aio`) | `Content-Security-Policy` (скрипты, шрифты, запросы только со своего сайта, чужие фреймы запрещены), `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, `server_tokens off` |
| Сторонние ресурсы | шрифт Manrope (OFL) раздаётся с самого сайта, запросов к Google нет, поэтому CSP без исключений |

Проверено в настоящем Chrome (DevTools Protocol): вход клиента и сотрудника, очередь, карточка заявки, `/admin`, кабинет клиента, «Мои заявки», «Помощь» открываются под CSP без единого нарушения; внедрённый inline-скрипт, чужой скрипт и запрос на чужой адрес блокируются; в `localStorage` пусто. В собранном коде нет `eval` и sourcemap, `npm audit` без уязвимостей.

## Что не проверено или не меняется

- Отмеченное «Запомнить меня» оставляет токен в `localStorage` до выхода или истечения срока: на чужом компьютере галочку ставить нельзя.
- `sessionStorage`, как и `localStorage`, читается любым скриптом страницы: при XSS токен можно украсть. Против этого работает CSP выше и отсутствие опасных API (в коде нет `dangerouslySetInnerHTML`, `innerHTML`, `eval`). Надёжное решение это `httpOnly`-кука с `SameSite` от бэкенда, тогда токен недоступен скриптам.
- Выход из кабинета не отзывает токен на сервере (у бэка нет такой ручки): до истечения срока (сутки) токен остаётся действительным.
- HSTS не включён: TLS должен завершаться на внешнем прокси, там и нужен `Strict-Transport-Security`.
- Демо-вход сотрудника (`ivanova` и др.) выдаёт неподписанный токен с `isAdmin` только для показа интерфейса: сервер такой токен отклонит, реальных данных он не открывает. Для рабочего окружения демо-вход стоит отключить.

## Что нужно от бэкенда и окружения

1. **`/external-api/` открыт всем.** Через nginx клиента наружу проксируется мок внешних систем без авторизации: любой может переключать банк, бюро и реестр (`setActive`) и читать данные реестра по ИНН. Экран `/admin` закрыт только в интерфейсе, сам запрос не защищён. Для рабочего окружения убрать этот прокси или защитить мок.
2. Токен в `httpOnly`-куке, ручка выхода, которая отзывает токен.
3. Ограничение числа попыток входа (`/users/login`, `/users/admin-login`); сейчас его нет.
4. Валидация тела запросов (см. `docs/backend-requirements.md`, 3.0.11) и защита от падения процесса (3.0.10).
