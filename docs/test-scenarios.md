# Пошаговые сценарии проверки
## Сценарий 1. Базовый минимальный сценарий. 
Пользователь создает заявку на кредит. Заявка одобрена. Пользователь получает деньги.
### Шаги воспроизведения
#### Шаг 1. Авторизуемся от лица пользователя
Переходим на главную страницу веб-приложения
```
http://127.0.0.1:8080/login
```
Используем следующие логин и пароль: 
```
{
  "login": "alfaAngelika",
  "password": "alfaAngelika!"
}
```
(для этого пользователя в системе предзагружены данные, как будто он уже давно работает с этим банком)
После авторизации загрузится главная страничка приложения с формой подбора продукта и списком уже когда-то созданных заявок.
Слева вверху бокового меню выбрана организация ООО "Кот не знает" (если у пользователя будет несколько организаций, переключаться можно здесь)
#### Шаг 2. Создаем заявку
Заполняем форму подбора кредита на главной странице: 

Для чего нужны деньги: купить оборудование

Сумма: 100000

Срок: 24 месяца

Нажимаем кнопку "подобрать"

#### Шаг 3. Выбираем продукт 
На основе заполненных данных приложение алгоритмически подобрало несколько вариантов кредитных продуктов. (алгоритм фильтрует мокированные продукты банка по минимальной и максимальной сумме, срокам кредитования)
Читаем условия каждого из вариантов. Нажимаем кнопку "выбрать" под первым вариантом.
#### Шаг 4. Отправляем заявку
На данном этапе внимательно смотрим на данные организации (они были вне нашей системы и хранятся в банке): проверяем, что отправляем заявку по правильной компании, если у нас их несколько.
Этот этап нужен для заполнения дополнительных полей, если они есть (могут быть добавлены при выборе определенного продукта, например тип залога) - при выборе варианта 1 ничего заполнять не нужно.
Подтверждаем данные, на следующей страничке ставим галочки о согласии на обработку персональных данных, в том числе из внешних источников, нажимаем большую красную кнопку "отправить в банк".

#### Шаг 5. Ожидаем решение по заявке
В личном кабинете отображается статус заявки и ориентировочное время ожидания

#### Шаг 6. Авторизуемся от лица оператора
Сначала нужно выйти из аккаунта пользователя или открыть новую вкладку в режиме инкогнито браузера.
Переходим на 
```
http://127.0.0.1:8080/staff/login
```
Вводим логин и пароль 
```
{
  "login": "alfaOperator1",
  "password": "alfaOperator1!"
}
```
Видим список заявок на кредиты. 

#### Шаг 7. Берем заявку в работу
Нажимаем кнопку "взять" рядом с новой заявкой по ООО "Кот не знает"

#### Шаг 8. Изучаем данные заявки
Нажимаем на заявку и попадаем в ее карточку с подробной информацией по заявке. В правой части экрана видим результаты оценки заявки моделью на основе данных банка, данных, запрошенных из бюро кредитных историй и единого государственного реестра.

#### Шаг 9. Принимаем решение по заявке. 
Система предлагает наилучшее с точки зрения модели решение, оператор может его утвердить или же выбрать другое - финальное слово всегда за оператором. 
Оставляем предложенное решение, нажимаем "одобрить"

#### Шаг 10. Снова авторизуемся под пользователем
Авторизуемся под тем же пользователем что подавал заявку

#### Шаг 11. Заходим на страничку заявки 
С главного экрана - выбираем в списке нашу последнюю заявку (она в статусе одобрена).
Видим статус заявки, условия и кнопку "подписать договор"

#### Шаг 12. Подписываем договор 
Нажимаем кнопку подписать, знакомимся с условиями договора, ставим галочку, подтверждаем подписание. Читаем сообщение о том, что в течение ближайшего времени деньги будут перечислены на расчётный счет компании (реальных транзакций с реальными деньгами произведено не будет)

#### Шаг 13. Радуемся деньгам
ураa~

## Сценарий 2. Работа сервиса в режиме проблем доступа к внешним сервисам

Мы сочли крайне актуальным продумать, как будет вести себя наш сервис при недоступности каких-то внешних систем. Сценарий описывает обработку заявки в случае если в момент скоринга внешние системы для получения информации оказались недоступными и скоринг не смог быть запущенным.
### Шаги воспроизведения
#### Шаг 1.  Авторизуемся от лица оператора
Переходим на 
```
http://127.0.0.1:8080/staff/login
```
Вводим логин и пароль 
```
{
  "login": "alfaOperator1",
  "password": "alfaOperator1!"
}
```
Видим список заявок на кредиты. 
#### Шаг 2. Моделируем отключение внешних систем
Переходим на панель мониторинга внешних систем
```
http://127.0.0.1:8080/admin
```
Для систем Кредитное бюро и Единый реестр смещаем переключатель в положение "выключено". Теперь на запросы нашего сервиса к этим системам будет возвращаться ошибка 503.
#### Шаг 3. Авторизуемся от лица пользователя
Переходим на главную страницу веб-приложения
```
http://127.0.0.1:8080/login
```
Используем следующие логин и пароль: 
```
{
  "login": "alfaAngelika",
  "password": "alfaAngelika!"
}
```
(для этого пользователя в системе предзагружены данные, как будто он уже давно работает с этим банком)
После авторизации загрузится главная страничка приложения с формой подбора продукта и списком уже когда-то созданных заявок.
Слева вверху бокового меню должна быть выбрана организация ООО "Кот не знает" (это организация, к которой у пользователя есть доступ).

#### Шаг 4. Создаем заявку
Заполняем форму подбора кредита на главной странице: 

Для чего нужны деньги: купить оборудование

Сумма: 100000

Срок: 24 месяца

Нажимаем кнопку "подобрать"

#### Шаг 5. Выбираем продукт 
Знакомимся с условиями предложенных продуктов. Нажимаем кнопку "выбрать" под первым вариантом.
#### Шаг 6. Отправляем заявку
Подтверждаем данные, ставим галочки о согласии на обработку персональных данных, нажимаем большую красную кнопку "отправить в банк".

#### Шаг 7.  Ожидаем решение по заявке
В личном кабинете отображается статус заявки и ориентировочное время ожидания.

#### Шаг 8. Авторизуемся от лица оператора
Сначала нужно выйти из аккаунта пользователя или открыть новую вкладку в режиме инкогнито браузера.
Переходим на 
```
/staff/login
```
Вводим логин и пароль 
```
{
  "login": "alfaOperator1",
  "password": "alfaOperator1!"
}
```
Видим список заявок на кредиты. 


#### Шаг 9. Берем заявку в работу
Нажимаем кнопку "взять" рядом с новой заявкой.

#### Шаг 10. Изучаем данные заявки
Нажимаем на заявку и попадаем в ее карточку с подробной информацией по заявке. Видим, что данные из реестра и бюро не были получены, скоринг не проведен. При полной недоступности систем оператор может на этом этапе принять решение полностью самостоятельно (получить информацию из других источников или принять решение на основе каких-то других оснований). Однако в предложенном сценарии оператор продолжит работу с заявкой после восстановления работоспособности внешних систем. 
На данном этапе можно попробовать нажать кнопку "Перезапустить скоринг" (под информационными блоками в нижней части страницы) - система будет думать дольше обычного, так как при отсутствии ответа от внешних систем, выполняется по два повторных контрольных запроса с разницей в 1 и 2 секунды - чтобы удостовериться что это не единичный потерянный запрос. Однако, пока системы отключены, новых данных загружено из них не будет.

#### Шаг 11. включаем системы
Переходим на панель мониторинга внешних систем
```
http://127.0.0.1:8080/admin
```
Для систем Кредитное бюро и Единый реестр смещаем переключатель в положение "включено".

#### Шаг 12. Перезапускаем автоматический скоринг
Снова переходим в режим просмотра информации по заявке. Под блоком информации о компании и скоринге (пустых) нажимаем "Перезапустить скоринг", немного ждем

#### Шаг 13. Принимаем решение по заявке. 
Смотрим на результаты скоринга и принимаем решение по заявке.
Оставляем предложенное решение, нажимаем "одобрить".

### Дополнительные сценарии проверки
Далее предполагается, что пользователь системы уже ознакомился с базовой функциональностью системы, поэтому этапы авторизации, создания заявки, принятия решения и т.п. не расписаны так подробно, как в основных сценариях.

#### Дополнительный сценарий 1 - недоступность систем банка
Отключить сервисы банка (от банка наш сервис получает актуальный список продуктов с актуальными условиями, проценты, минимальные суммы и т.д.). От пользователя: попытаться создать заявку, получить сообщение что сервисы банка недоступны. Вернуться на главный экран, увидеть что заявка в статусе черновика. Включить сервисы банка. Продолжить заполнение заявки (все введенные данные сохранились)

#### Дополнительный сценарий 2 - отклонение заявки
От пользователя: создать заявку. От оператора: отклонить заявку, указать причину и по желанию - комментарий. От пользователя: зайти в личный кабинет и увидеть причину отказа.

#### Дополнительный сценарий 3 - несколько компаний у одного пользователя
Зайти под пользователем login: alfaSergey, password: alfaSergey! 
У этого пользователя несколько компаний, одна из них ИП, другая - с нулевыми доходами за последний год. Между ними можно переключаться и подать заявку от любой (или каждой) из них. На главном экране отображаются заявки только по выбранной в данный момент организации.

#### Дополнительный сценарий 4 - недействительная компания
Зайти под пользователем login: alfaSergey, password: alfaSergey! 
У этого пользователя несколько компаний, в левом верхнем углу выбрать "ООО Таинственный сад" и подать от нее заявку. От оператора - перейти к заявке. Из реестра получена информацию о том, что у сейчас компании статус "не действителен" - заявку нужно отклонить. (Предположим, что в банке эта информация еще не была синхронизирована с реестром, поэтому у пользователя был доступ к кабинету). От оператора - отклонить заявку.

#### Дополнительный сценарий 5 - ручное принятие решения при отключенных внешних системах
Отключить Кредитное бюро и Единый реестр. От пользователя - создать заявку. От оператора - зайти на страницу заявки, увидеть, что сервисы недоступны. Проверить информацию об организации по другим источникам. Принять решение по заявке и внести его в систему. От пользователя - увидеть решение по заявке. Включить Кредитное бюро и Единый реестр.

#### Дополнительный сценарий 6 - совместная обработка заявок несколькими операторами
Зайти под учетной записью login: alfaOperator2, password: alfaOperator2!. Увидеть что часть заявок находится на обработке у другого сотрудника. Просмотр карточки таких заявок не заблокирован (может быть кто-то из сотрудников захочет посмотреть аналогичные своей текущей заявке для справки), однако блок принятия решения не доступен.
