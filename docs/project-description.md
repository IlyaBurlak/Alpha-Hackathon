# Назначение проекта
Веб-сервис "Бизнес-кредиты" предназначен для сквозной обработки кредитной заявки - от её создания пользователем, через обработку операторами банка, до зачисления средств на счет. 
### Для кого
Сервис доступен для двух ролей: пользователь (руководитель компании или другой представитель бизнеса, уполномоченный распоряжаться финансами) и оператор банка.
### Демо данные
 При работе системы будут имитироваться запросы к внешним системам - бюро кредитных историй, единый государственный реестр юридических лиц, прочие банковские системы. В качестве мока мы написали дополнительный сервер (externalSystemsMock), к которому будут выполняться настоящие http запросы в реальном времени при работе нашей системы. Мок запускается внутри докера рядом с сервером самого приложения. Данные о продуктах банка, компаниях и пользователях, предложенные в демо версии решения - сгенерированы и не являются юридически значимыми. Любые совпадения с реальными людьми и компаниями случайны.
### Преимущества для пользователя
* **Получение рекомендаций по продукту**: пользователь может ввести только сколько ему нужно денег и на какой срок он рассчитывает кредит, а система сама подберет подходящие продукты и подробно и наглядно покажет разницу между ними, составит график выплат и подсветит преимущества разных продуктов. Примечание: продукты выбираются системой алгоритмически по условиям продуктов: учитываются возможные минимальные суммы кредитования, сроки и т.д.
* **Удобный выбор продукта**: продукт можно выбрать прямо на странице умного подбора, оптимальный с точки зрения системы вариант будет подсвечен как рекомендованный.
* **Сокращение объёма ручного ввода**: Не нужно вручную вносить все данные компании: если вы действующий клиент банка, в заявке вы только убедитесь в корректности подстановки. Вручную вводится только сумма кредита.
* **Контроль статуса заявки в любой момент времени**: в личном кабинете в реальном времени показывается статус заявки. Здесь же показывается график выплат в случае одобрения кредита.
* **Обоснование отказа**: При отказе в выдаче кредита причина отказа будет указана в карточке заявки.
* **Просмотр истории и графика выплат**: всё в одном сервисе

### Преимущества для оператора банка
* **Удобный просмотр всех заявок**: оператору доступен одновременный просмотр всех активных заявок с разбивкой по статусам.
* **Распределение заявок между операторами**: в начале обработки заявки оператор становится "ответственным" за неё. Другие операторы увидят, что заявка уже обрабатывается, не будут делать ту же работу и не смогут перезаписать решение ответственного оператора другими данными.
* **Вся информация по заявке на одной странице**: дашборд с доходами компании, юридические данные, информация по долгам и скоринг - всё в одном месте
* **Автоматическое выполнение запросов во внешние системы**: при подаче заявки автоматически запрашиваются данные о компании в  Бюро кредитных историй и Едином Государственном реестра (юридических или физических лиц в зависимости от типа заявки). Примечание: В качестве внешних систем используется дополнительный мок-веб-сервер, имитирующий ответы этих систем.
* **Автоматический скоринг каждой заявки**: сразу после получения данных от внешних систем запускает ml-скоринг заявки. Модель оценивает риски и выдает рекомендацию - одобрить кредит или нет. На прочтение рекомендации и конкретных рисков оператору потребуется в десятки раз меньше времени, чем если бы он запрашивал и сводил все эти цифры вручную.
*  **Последнее слово за оператором**: модель оценивает все риски и выдает оценку, предоставляя оператору рекомендованное решение. Однако, любая модель может галлюцинировать, поэтому оператор экспертным взглядом просматривает результат перед одобрением/отклонением. Обязательным включением оператора в процесс исключаются ошибки ответа из-за, например, нестандартных данных, отсутствовавших в момент обучения модели.
* **Гибкая система принятия решений**: обычно заявка либо одобряется, либо отклоняется. Однако оператор, если сочтет необходимым, может предложить альтернативные условия выдачи кредита (например изменить сумму или ставку). 
* **Работа системы в условиях неработоспособности внешних систем**: внешние системы могут внезапно оказываться недоступными по разным причинам. Наш сервис поддерживает несколько сценариев работы для подобных случаев. При необходимости оператор может вручную собрать данные об организации и принять решение, оставаясь в знакомом сервисе. Клиент не заметит возникших проблем.  Примечание: наш дополнительный mock сервис позволяет промоделировать отключение внешних систем и протестировать наш сервис в таких условиях. При отсутствии ответа от внешней системы,  перед сохранением информации об отсутствии доступа, выполняется два повторных запроса с небольшими промежутками по времени.



# Пошаговые сценарии проверки
## Сценарий 1. Базовый минимальный сценарий. 
Пользователь создает заявку на кредит. Заявка одобрена. Пользователь получает деньги.
### Шаги воспроизведения
#### Шаг 1. Авторизуемся от лица пользователя
Переходим на главную страницу веб-приложения
```
http://127.0.0.1:8080/login
```
Используем следующие логин и пароль: 
```
{
  "login": "alfaAngelika",
  "password": "alfaAngelika!"
}
```
(для этого пользователя в системе предзагружены данные, как будто он уже давно работает с этим банком)
После авторизации загрузится главная страничка приложения с формой подбора продукта и списком уже когда-то созданных заявок.
Слева вверху бокового меню выбрана организация ООО "Кот не знает" (если у пользователя будет несколько организаций, переключаться можно здесь)
#### Шаг 2. Создаем заявку
Заполняем форму подбора кредита на главной странице: 
Для чего нужны деньги: купить оборудование
Сумма: 100000
Срок: 24 месяца
Нажимаем кнопку "подобрать"
#### Шаг 3. Выбираем продукт 
На основе заполненных данных приложение алгоритмически подобрало несколько вариантов кредитных продуктов. (алгоритм фильтрует мокированные продукты банка по минимальной и максимальной сумме, срокам кредитования)
Читаем условия каждого из вариантов. Нажимаем кнопку "выбрать" под первым вариантом.
#### Шаг 4. Отправляем заявку
На данном этапе внимательно смотрим на данные организации (они были вне нашей системы и хранятся в банке): проверяем, что отправляем заявку по правильной компании, если у нас их несколько.
Этот этап нужен для заполнения дополнительных полей, если они есть (могут быть добавлены при выборе определенного продукта, например тип залога) - при выборе варианта 1 ничего заполнять не нужно.
Подтверждаем данные, на следующей страничке ставим галочки о согласии на обработку персональных данных, в том числе из внешних источников, нажимаем большую красную кнопку "отправить в банк".

#### Шаг 5. Ожидаем решение по заявке
В личном кабинете отображается статус заявки и ориентировочное время ожидания

#### Шаг 6. Авторизуемся от лица оператора
Сначала нужно выйти из аккаунта пользователя или открыть новую вкладку в режиме инкогнито браузера.
Переходим на 
```
http://127.0.0.1:8080/staff/login
```
Вводим логин и пароль 
```
{
  "login": "alfaOperator1",
  "password": "alfaOperator1!"
}
```
Видим список заявок на кредиты. 

#### Шаг 7. Берем заявку в работу
Нажимаем кнопку "взять" рядом с новой заявкой по ООО "Кот не знает"

#### Шаг 8. Изучаем данные заявки
Нажимаем на заявку и попадаем в ее карточку с подробной информацией по заявке. В правой части экрана видим результаты оценки заявки моделью на основе данных банка, данных, запрошенных из бюро кредитных историй и единого государственного реестра.

#### Шаг 9. Принимаем решение по заявке. 
Система предлагает наилучшее с точки зрения модели решение, оператор может его утвердить или же выбрать другое - финальное слово всегда за оператором. 
Оставляем предложенное решение, нажимаем "одобрить"

#### Шаг 10. Снова авторизуемся под пользователем
Авторизуемся под тем же пользователем что подавал заявку

#### Шаг 11. Заходим на страничку заявки 
С главного экрана - выбираем в списке нашу последнюю заявку (она в статусе одобрена).
Видим статус заявки, условия и кнопку "подписать договор"

#### Шаг 12. Подписываем договор 
Нажимаем кнопку подписать, знакомимся с условиями договора, ставим галочку, подтверждаем подписание. Читаем сообщение о том, что в течение ближайшего времени деньги будут перечислены на расчётный счет компании (реальных транзакций с реальными деньгами произведено не будет)

#### Шаг 13. Радуемся деньгам
ураa~

### Дополнительные сценарии проверки
Далее предполагается, что пользователь системы уже ознакомился с базовой функциональностью системы, поэтому этапы авторизации, создания заявки, принятия решения и т.п. не расписаны так подробно, как в основных сценариях.

#### Дополнительный сценарий 1 - недоступность систем банка
Отключить сервисы банка (от банка наш сервис получает актуальный список продуктов с актуальными условиями, проценты, минимальные суммы и т.д.). От пользователя: попытаться создать заявку, получить сообщение что сервисы банка недоступны. Вернуться на главный экран, увидеть что заявка в статусе черновика. Включить сервисы банка. ## План развития проекта
* Автоматический перезапуск скоринга при восстановлении внешних систем. Внешние системы, в случае фиксации случая отсутствия ответа, будут пинговаться с определенной частотой. При выходе их на связь - автоматический последовательный запрос данных и перезапуск скоринга для заявок без оценки.
* Отправка уведомлений ответственным сотрудникам банка в случае потери связи с внешними системами о необходимости принять меры - отдать распоряжение операторам использовать другие ресурсы, написать в тех. поддержку внешних систем и т.п.
* Подробное логирование запросов на сервер
* Сохранение истории действий операторов и построение характеристик их работы
* Приоритетность заявок в зависимости от статуса компании и других условий
* Возможность "отзыва" заявки пользователем пока она не была обработана оператором
* Оплата и отслеживание прогресса по оплате
* Пагинация при работе с заявками
