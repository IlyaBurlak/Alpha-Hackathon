# Полный список данных, которые должны отдать бэкенд и ML

Документ собран по тому, что реально показывают оба кабинета (дизайн «Кредитный кабинет МСБ» и «Кабинет сотрудника»). Это **единый список для снятия всех моков с фронта**. Детали по приоритетам и номерам пунктов — в [`backend-requirements.md`](./backend-requirements.md), список того, что сейчас замокано, — в [`frontend-mocks.md`](./frontend-mocks.md), сценарии пользователей — в `CLAUDE.md`.

Обозначения в колонке «Сейчас»: **есть** — бэк уже отдаёт; **частично** — отдаёт, но не всё или не тем способом; **нет** — фронт использует мок. Деньги — числа в рублях, даты — ISO 8601 в UTC, сроки в запросах `{ units, value }`, в ответах дополнительно ожидается `termInMonths`.

## 2. Общие требования

- **Роли.** В JWT: `role: 'entrepreneur' | 'employee'` (сейчас `isAdmin` только у оператора; клиент понимает и его). Все эндпоинты сотрудника — только для роли `employee`, иначе `403`. Клиентские эндпоинты отдают только заявки владельца.
- **Ошибки.** HTTP-коды по смыслу (`400` валидация, `401` нет токена или пара логин-пароль неверна, `403` нет прав, `404` не найдено, `409` конфликт состояния, `503` внешний сервис недоступен) и тело `{ "error": "Текст для человека" }`. Клиент показывает `error` как есть. Сейчас почти всё `500`.
- **Идентификаторы.** Для заявки клиента нужен один номер (`number`, как «№ 204517»), общий для обоих кабинетов.
- **Обновления.** Клиент опрашивает заявку клиента раз в 5 секунд, пока она «На рассмотрении», раз в секунду при выдаче, список сотрудника раз в 4 секунды, пока есть заявки на скоринге. Допустима замена на push (SSE или WebSocket).
- **Списки.** Для сотрудника: фильтры `status`, `assigneeId`, `q` (номер, название, ИНН), `sort`, страницы.

### 3.4. Оценка («шанс одобрения»)

Один и тот же объект для предложения (шаг «Вариант», до отправки) и для заявки (после рассмотрения):

```json
"scoring": {
  "score": 72,
  "factors": [
    { "title": "Возраст бизнеса", "description": "6 лет на рынке", "points": 15, "advice": null },
    { "title": "Кредитная история", "description": "Есть просрочка до 30 дней", "points": -10,
      "advice": "Закройте просрочку, через 3 месяца оценка вырастет" }
  ]
}
```

Фронт сам делает из балла метки: от 80 «Высокий», от 60 «Хороший», от 45 «Средний», иначе «Низкий», а «Рекомендуем» ставит варианту без залога при балле от 60, иначе варианту с залогом. Для отказа нужны отрицательные факторы с `advice`. Эта оценка предварительная: итоговое решение принимает банк, это написано в интерфейсе.

## 5. ML-сервис

Сейчас в `main` у `ml/` только `/health`, а в ветке `feature/ml-score-service` — заглушка `POST /score` с контрактом `features → pd, model_version, factors`. Бэкенд вызывает `ML_SCORING_API/score` и пока подставляет в заявку фиксированные значения (`pd: 0.1`, факторы — список строк).

### 5.1. Когда вызывается

1. **До отправки** — для каждого предложения на шаге «Вариант» (предварительная оценка для клиента, нужна быстро, до 2 секунд, лучше синхронно). Для вариантов с залогом признак залога учитывается.
2. **После отправки** — полный скоринг при рассмотрении (допустимо асинхронно, «обычно до 15 минут»), результат виден сотруднику и, как итоговая оценка, клиенту.

### 5.2. Что ML получает (признаки)

Из контракта ветки `feature/ml-score-service`: `business_age_months`, `is_sole_proprietor`, `okved_group`, `avg_revenue_12m`, `revenue_cv` (разброс выручки), `expense_ratio`, `debt_service_ratio`, `max_delinquency_days_12m`, `active_loans_count`, `requested_to_monthly_revenue`, `term_months`. Чтобы воспроизвести факторы интерфейса, нужны ещё: `is_secured` и `collateral_ltv`, `arbitration_cases`, `tax_debt`, `has_stable_turnover` (или помесячные обороты), `requested_amount`, `product_id`, `bank_client_since_months`. Источники: анкета, единый реестр, БКИ, обороты по счёту, ФНС, картотека арбитражных дел.

### 5.3. Что ML возвращает

| Поле | Зачем | Замечание |
| --- | --- | --- |
| `pd` (0–1) | вероятность дефолта, показывается сотруднику | есть в заглушке |
| `score` (0–100, выше — лучше) | главная цифра интерфейса, пороги 45 (отказ) и 75 (автоодобрение) | нужно: либо ML считает, либо бэк переводит из `pd`; в дизайне `pd = 0,45 / (1 + exp((score − 48) / 8))`, то есть `score = 48 + 8 · ln(0,45 / pd − 1)` |
| `risk_class` (A–E) | «Класс риска» | A ≥ 80, B ≥ 70, C ≥ 60, D ≥ 45, E ниже |
| `suggested_rate` | «Ставка по модели» | базовая ставка продукта плюс надбавка за риск (−1, +1, +3,5 или +6 пунктов по баллу); можно считать на бэке |
| `factors[]` | «Вклад факторов» | см. ниже |
| `model_version`, `updated_at` | «Модель SME-PD v2.3, обновлена …» | `updated_at` нужно добавить |

Формат фактора для интерфейса: `{ title, description, points, advice? }`, где `points` — на сколько балл сдвинулся от базового уровня 40 (плюс повышает шанс), `description` — человеческий текст («6 лет на рынке», «42 % годовой выручки, выше порога 35 %»), `advice` — совет клиенту для отрицательных факторов. В заглушке `impact > 0` повышает риск, а `label` — готовая подпись: нужно привести к одному знаку и добавить `description` и `advice`. Показываются все факторы (в дизайне до семи), а не только топ-5.

### 5.4. Рекомендация системы

Сейчас считается правилами на клиенте (мок): отказ при проваленной проверке или балле ниже 45; запрос данных при арбитраже или налоговой задолженности; одобрение при балле от 75 и всех пройденных проверках; иначе предложить 75 % или 55 % суммы (в зависимости от балла) на срок плюс 12 месяцев. Нужно, чтобы это делал бэк или ML и отдавал `recommendation` с причинами.

## 6. Статусы и переходы

**Клиент:** `DRAFT` → (отправка) `SUBMITTED` → `APPROVED` → (подпись) `PAYOUT` → `ISSUED`. Из `SUBMITTED`: `REJECTED`, `WITHDRAWN`. Из рассмотрения также: «предложены другие условия» и «запрошены данные» (в дизайне клиента нет, нужны экраны и статусы).

**Сотрудник:** `scoring` → `ready` → `approved` | `rejected` | `offer` | `clarify`; из `offer` и `clarify` — обратно в `ready` («Изменить решение») или (по ответу клиента) в `approved` / `rejected`.

**Соответствие:** `ready` и `scoring` клиент видит как `SUBMITTED`; `approve` → `APPROVED`; `reject` → `REJECTED`.
