# Клиент (веб-интерфейс)

Веб-интерфейс «Умного кредитного кабинета предпринимателя» для малого и микробизнеса.

## Назначение

Один клиент, два кабинета, роль берётся из JWT:

- **Кабинет предпринимателя** (`/cabinet`): подбор кредита, оформление заявки, статус, подпись договора.
- **Кабинет сотрудника банка** (`/staff`): очередь заявок, проверки, ML-скоринг, кредитное решение.

Клиент общается только с `server` по HTTP (`/api`), в `ml` напрямую не ходит. Охрана маршрутов на клиенте (`RequireRole`) нужна только для удобства, права проверяет сервер.

**Стек:** React 19, TypeScript (strict), Vite, CSS-модули, MobX, react-router.

## Зачем отдельный контейнер

Клиент собирается в статику и отдаётся nginx:
- Один публичный порт (8080): статика, `/api` на сервер, `/external-api` на мок внешних систем, `/swagger` на Swagger сервера
- Заголовки безопасности (CSP, `X-Frame-Options`, `nosniff` и др.) задаются в `nginx.conf`
- Контейнер работает без root, есть healthcheck

## Экраны и маршруты

| Маршрут | Экран | Где живёт |
| --- | --- | --- |
| `/login` | Вход предпринимателя | `pages/login` |
| `/cabinet` | Главная: подбор кредита, последние заявки | `pages/home` |
| `/cabinet/applications` | Мои заявки: активные и завершённые | `pages/applications` |
| `/cabinet/applications/:id/edit` | Оформление черновика: вариант, данные, отправка | `pages/application-edit`, `widgets/application-wizard` |
| `/cabinet/applications/:id` | Заявка: статус, шаги, условия, график платежей | `pages/application` |
| `/cabinet/help` | Помощь | `pages/help` |
| `/staff/login` | Вход сотрудника | `pages/staff-login`, `features/staff-login` |
| `/staff`, `/staff/mine`, `/staff/done` | Очередь, мои заявки, решённые | `pages/staff-queue`, `widgets/staff-queue` |
| `/staff/applications/:id` | Заявка сотрудника: данные, проверки, скоринг, решение | `pages/staff-application`, `widgets/staff-application-review`, `features/decide-application`, `features/assign-application` |
| `/admin` | Панель внешних систем (без входа, демо-инструмент) | `pages/admin` |

Сессия (JWT) живёт 24 часа. Без «Запомнить меня» токен лежит в `sessionStorage` и исчезает при закрытии вкладки.

## Какие данные настоящие

- **Настоящие:** вход, организации, продукты и предложения, создание и отправка заявки, статус, подпись, решения реального оператора (`alfaOperator1/2`), результат ML.
- **Моки на клиенте** (`api/mocks/` внутри нужного среза, данные бэка всегда приоритетнее): профиль и реквизиты компании, часть полей заявки, стадии проверки, выдача денег, демо-сотрудники (`ivanova`, `orlov`, `kim`) и их очередь.
- Цель кредита, выбранный продукт и анкета шага «Данные» хранятся в `localStorage` до отправки.

## Архитектура: Feature-Sliced Design

Слои сверху вниз; слой импортирует только нижние, срезы одного слоя друг о друге не знают, наружу срез отдаёт только `index.ts`.

| Слой | Что в нём | Пример |
| --- | --- | --- |
| `app` | провайдеры, роутер, корневой стор, глобальные стили | маршруты `/cabinet` и `/staff`, защита по роли |
| `pages` | экраны целиком | «Мои заявки», очередь сотрудника |
| `widgets` | крупные блоки интерфейса | рамка кабинета, мастер заявки |
| `features` | действия пользователя | вход, решение по заявке, назначение ответственного |
| `entities` | бизнес-сущности: модель, API, базовый UI | заявка, организация, сессия, сотрудник |
| `shared` | переиспользуемое без бизнес-логики | UI-кит, API-клиент, утилиты |

Срез делится на сегменты `ui`, `model`, `api`, `lib`, `config`. Границы слоёв проверяет `steiger` в `npm run lint` и в CI. Подробные правила: `CLAUDE.md` в этой папке.

Токены дизайна (цвета, шрифт Manrope) лежат в `src/shared/ui/theme/tokens.css`, базовые компоненты в `src/shared/ui`. Экраны входа и админки используют `@alfalab/core-components`.

## Запуск

### Локально (разработка)
```bash
cd client
npm install
npm run dev
```

`npm run dev` сам поднимает `server`, `ml` и мок внешних систем в Docker (с портами на `127.0.0.1`), затем запускает Vite на `http://localhost:5173` с hot reload. Остановить бэкенд: `npm run backend:down`.

### Через Docker Compose
Из корня репозитория:
```bash
cp .env.example .env          # задайте JWT_SECRET
docker compose up -d --build --wait
```

Приложение: `http://localhost:8080` (порт задаёт `WEB_PORT`). Healthcheck: `GET /`. Пересобрать всё целиком: `npm run rebuild` в `client/`.

### Из готового образа
```bash
docker run -d --name alpha -e JWT_SECRET=любая-строка -p 8080:8080 ghcr.io/ilyaburlak/alpha-hackathon:latest
```

Учётные записи для входа: корневой `README.md`.

## Swagger

Документация API сервера открывается на `http://localhost:8080/swagger/` (nginx проксирует `/swagger` на сервер, и в compose, и в образе). Кнопка «Try it out» в Swagger ходит на `http://localhost:<порт сервера>`, а не на 8080, поэтому из контейнера она не сработает, пока в `server/src/swagger.ts` не будет относительного адреса (`url: '/'`); это правка команды сервера. Просмотр описания эндпоинтов работает.

## Конфигурация

Клиент не читает переменных окружения: адреса задаёт nginx (`nginx.conf` для compose, `aio/nginx.conf` для образа) и dev-прокси Vite (`vite.config.ts`).

| Путь | Куда проксируется |
| --- | --- |
| `/api/*` | `server:3001` |
| `/external-api/*` | `external-systems:5006/api/*` |
| `/swagger` | `server:3001/swagger` |

## Проверки

```bash
cd client
npm run lint     # oxlint + steiger (границы FSD)
npm test         # vitest
npm run build    # tsc -b + vite build
```

Тесты лежат рядом с кодом (`*.test.ts(x)`). Те же шаги гоняет CI (`client-lint`, `client-test`, `client-build`).

## Ограничения

- Демо: данные синтетические, реестры и БКИ — мок внешних систем.
- Не поддерживается бэком, поэтому не работает: отзыв заявки, запрос данных у клиента с загрузкой документов, анкета шага «Данные» на сервер не уходит.
- Панель `/admin` без защиты, не публикуйте стенд в открытую сеть.
