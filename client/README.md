# Клиентская часть приложения для Альфа хакатона

Веб-интерфейс с двумя кабинетами: предприниматель подаёт заявку на кредит, сотрудник банка рассматривает её и принимает решение. Клиент общается только с `server` по HTTP (`/api`), в `ml` напрямую не ходит.

**Стек:** React 19, TypeScript (strict), Vite, дизайн-система [`@alfalab/core-components`](https://core-ds.github.io/core-components/master/?path=/docs/intro--docs). Состояние на MobX планируется, в проект пока не добавлено.

## Выбор архитектуры: Feature-Sliced Design (FSD)

### Почему FSD

- **Два кабинета в одном приложении.** У кабинета предпринимателя и кабинета сотрудника разные экраны, но общие сущности: заявка, организация, пользователь, статус. FSD позволяет один раз описать сущность и использовать её в обоих кабинетах, не копируя код.
- **Параллельная работа команды.** Код делится по бизнес-смыслу (`application-wizard`, `staff-dashboard`), а не по технологии (`components`, `utils`). Люди работают в разных срезах и почти не конфликтуют.
- **Предсказуемые зависимости.** Слой импортирует только нижние слои, а срезы одного слоя не знают друг о друге. Изменение в одном экране не ломает другие, а циклических импортов нет.
- **Лёгкий вход и рост.** Новому разработчику понятно, где искать код и куда класть новый. Новый экран или действие добавляется новым срезом, старый код не переписывается.
- **Правила проверяются автоматически.** Границы слоёв можно закрепить линтером, а не договорённостями на словах.

### Слои (сверху вниз)

| Слой | Что в нём | Пример в проекте |
| --- | --- | --- |
| `app` | провайдеры, роутер, корневой стор, глобальные стили | роутинг `/cabinet` и `/staff`, защита по роли |
| `pages` | экраны целиком, собирают нижние слои | «Мои заявки», дашборд сотрудника |
| `widgets` | крупные самостоятельные блоки интерфейса | шапка кабинета, очередь заявок |
| `features` | действия пользователя с бизнес-смыслом | вход, подача заявки, решение по заявке |
| `entities` | бизнес-сущности: модель, API, базовый UI | заявка, организация, сессия |
| `shared` | переиспользуемое без бизнес-логики | API-клиент, константы, утилиты |

Каждый срез делится на сегменты по назначению: `ui`, `model`, `api`, `lib`, `config`. Наружу срез отдаёт только `index.ts`.


Бэк и ML для разработки поднимаются из корня репозитория, подробности в корневом `README.md`.
